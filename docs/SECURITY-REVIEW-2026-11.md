# Security review, November 2026

Scope: everything that crosses a trust boundary, meaning wire messages from paired devices, peer-influenced filesystem writes, network fetches, OS commands, remote-control surfaces, secrets, the browser-extension bridge, and the server (`apps/server`).

Threat model: a paired device may be compromised, lost or buggy. The relay server and the network are untrusted for confidentiality and integrity. A web page may be hostile.

Status values: **fixed** (a regression test is named), **partly fixed**, and **open** (the reason is given).

Line numbers refer to the tree after the fixes.

Totals: 3 high, 21 medium, 24 low. Fixed: 3 high, 18 medium and 7 low. Partly fixed: 1 low.

| H1 | `crates/mdcore/src/crypto.rs:25-43`, `transport/mod.rs:382` (`handle_incoming`), `transport/relay.rs:571-598`, `engine/ble.rs:143-156` | Envelopes carry no sender, recipient, time or counter in their authenticated data. Control messages are not de-duplicated. Over the relay, the sender is whatever the server says; over BLE, it is an unauthenticated `Hello`. So the relay server (or anyone who recorded traffic) can replay an old ciphertext, such as `input` text plus Enter, `open_url`, `action: lock` or `media_cmd`, and attribute it to any device. It decrypts and is acted on. | **Fixed** (envelope v2, `transport/envelope.rs`). The AEAD associated data binds the version, sender and recipient node ids, a random 128-bit `mid` and the send time in ms; the header travels in the clear and any change breaks the tag. The receiver checks `dst` is itself, `src` is the link's sender (the pinned key over QUIC, the server's `from` on the relay, the `Hello` on BLE), the time is within ±5 min (skew per device in Connection diagnostics), and the `mid` is new for that sender. Ids are kept for the window, and those that came over the relay or BLE are appended to `env_seen.log` before use, so a restart does not reopen it. Every envelope is sealed for one recipient (broadcasts are sealed per device). Negotiation: `env: 2` in status and `addr_update`; v2 goes only to devices that said it; v1 is still taken from a device until it is seen sending v2, then refused (downgrade, remembered across restarts). `CoreConfig::envelope_v2: false` plays an older app. Refusals are counted per device (replay, stale, downgrade, wrong recipient, spoofed) and logged without content. Tests: `crates/mdcore/tests/envelope.rs` (relay and BLE replays, window, recipient, spoofed sender over BLE and relay, v1 and v2 interop, downgrade, restart) and unit tests in `transport/envelope.rs`. **Per-device authenticity (2026-11, `env: 3`):** every version 2 envelope to a device that says `env: 3` is signed with the sender's device key (Ed25519, via the `rcgen`/`ring` key the QUIC certificate uses; no new dependency) over a label, the AAD header, the nonce and the ciphertext (`envelope::signed_bytes`), and checked against the key pinned for `src`, on every link (QUIC included: cheap and uniform). A sender that never met the recipient directly adds its public key (`pk`), taken on first use only where no key is pinned (the same TOFU as QUIC; a key differing from a pin is never taken). Once a device sent a signed envelope that checked out, its unsigned ones are refused (`unsigned`, persisted in kv `env_sig_peers`), and a signature that isn't the pinned key's is refused (`bad_signature`). Trusting a device's new key resets both downgrade marks (`Guard::reset`, the open item from the envelope work). `CoreConfig::envelope_sig: false` plays an app from before. Binary media records are not envelopes and are not signed. Cost (unit test `signing_cost_per_message`, release build, 512-byte body): sign 17 µs, verify 55 µs, against 9 µs seal / 3 µs open; +97 bytes per message. Tests: `tests/envelope.rs` (`a_paired_device_cannot_pass_as_another_over_bluetooth_once_signed`, `the_relay_cannot_attribute_a_forged_signed_envelope`, `an_app_from_before_signatures_still_talks_both_ways`, `trusting_a_new_key_resets_the_downgrade_marks`) and unit tests in `transport/envelope.rs`. Remaining: a device that never met the sender directly and has no pin takes the first key it is sent (TOFU, as QUIC); the registry does not carry `env` (the server is untrusted for it). Desktop and Android ship together through the shared core. |
| H2 | `apps/server/src/pair.rs:181` (`create`) | `/pair/create` lets a caller choose its own `code` and answers 409 when another account's live pairing already uses it. Creates were not limited. An attacker with a free account could walk all 10^6 codes in minutes, then `/pair/claim` the hit. That gives a session on the victim's account and the victim's `code_box`, which opens with the now-known code and yields the device key. | **Fixed.** Chosen codes are limited to 5 per account and 120 server-wide per minute, counted before the code is checked. Live pairings are capped at 10k. Test: `pair::tests::chosen_codes_cannot_be_walked_to_find_another_accounts_pairing`. |
| H3 | `apps/server/src/relay.rs:118` (`Queue`) | Each connection's outgoing queue was unbounded. A device that stops reading, plus a sender within its 4 MiB/s budget (or `/signal` posts, which are not budgeted), grows server memory without limit. | **Fixed.** Queued bytes are counted per connection, capped at 16 MiB. Past the cap the sender gets `offline` and signals fall back to FCM. Test: `relay::tests::a_device_that_stops_reading_cannot_make_the_server_hold_frames_without_end`. |

## Checked and fine

- **Network fetch**
  - Only http and https are allowed.
  - The resolver guard pins checked IPs, which defeats DNS rebinding, and every redirect is checked again.
  - Size caps are enforced while streaming, there is no gzip, and no proxy is taken from the environment.
  - `open_url` and Read later accept http(s) only.
- **Commands**
  - No shell is used on peer data.
  - `lp` gets `--` before the file and only locally listed printers.
  - AppleScript targets only fixed apps with integer values.
  - `netsh` XML is escaped.
  - `commands_run` runs only user-written text.
- **Extension bridge**
  - The Unix socket folder is 0700 and the socket 0600.
  - The Windows token comparison is constant-time.
  - Frames are capped at 1 MB, and requests are a closed enum.
  - Uploads have checked ids and a 25 MB cap.
  - Manifests are pinned to the extension ids.
- **File transfers**
  - `safe_name` and `safe_folder` strip traversal, drive letters and UNC paths.
  - `move_into` claims names with `create_new`, so no file is overwritten.
  - Folder-sync paths are checked with `rel_ok` and `inside()`, and symlinks are not followed.
  - Browse uses canonicalize plus a prefix check.
- **Server**
  - Every device, signal and relay route requires a JWT.
  - Every query is filtered by the token's `user_id`.
  - The relay only forwards within the same account.
  - Pairing codes come from OsRng without modulo bias, live 5 minutes and are single-use.

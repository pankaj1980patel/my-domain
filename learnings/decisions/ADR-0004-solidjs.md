# ADR-0004 — SolidJS + TypeScript for the desktop UI

- **Status:** Accepted (2026-11-01). Implemented in Phase 3.
- **Phase:** 3

## Context
The desktop UI is one 615-line vanilla-JS file
(the old `apps/desktop/src/main.js`, replaced 2026-11-02) that builds DOM by
hand. The feature catalogue adds dozens of screens: grant editor, media
controller, file browser, screen viewer, and more. Vanilla JS won't scale to that.

## Options considered
React + TS (biggest ecosystem), Svelte + TS, SolidJS + TS, or keeping vanilla JS.

## Decision
**SolidJS + TypeScript, built with Vite.** This was the owner's choice. Reasons it fits:
- JSX looks like React, so it's familiar coming from Node/React.
- *Fine-grained reactivity* (signals): only the exact DOM node that depends on a
  value updates, with no virtual-DOM diffing. That's good for high-frequency
  updates like live peer status, media position and transfer progress.
- Small runtime, well suited to Tauri's "small app" goal.
- Types generated by `tauri-specta` (ADR-0003) flow straight into components.

## Consequences
- ➕ Typed end to end: Rust command → generated TS → Solid component.
- ➖ The ecosystem is smaller than React's. We use plain CSS plus a small headless
  component library (e.g. Kobalte) rather than React-only libraries.
- ➖ Solid's rules differ from React's: components run **once**, and you must not
  destructure props, or you lose reactivity. These gotchas get documented in
  `10-desktop.md` as we meet them.

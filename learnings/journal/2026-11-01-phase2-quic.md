## What changed
| Commit | Change |
|---|---|

## Decisions made along the way
- **Incremental, not big-bang.** QUIC was added as a new ladder rung that
  registers in `ws_conns` like every other link, so the rest of the engine
  worked unchanged. All tests stayed green at each step.
- **The `Engine` owns the runtime, the context holds a handle.** Avoids a
  reference cycle and a tokio panic. See [06-async-tokio.md](../06-async-tokio.md).
- **Who dials on a punched path:** the lower node id. A deterministic choice
  with no extra message needed.
- **`ring` as the crypto backend** (not aws-lc): it cross-compiles to Android
  with just the NDK's clang.
- **Behaviour change, done deliberately:** the default is now QUIC. The old
  "chat over UDP by default" test was renamed `chat_over_udp_when_quic_is_off`
  (with `auto_quic: false`), and a new test asserts the QUIC default. Changing a
  test's *meaning* belongs in a commit message, not hidden.
- **Peer authentication is still deferred to Phase 4.** Documented in code and
  in [03-networking.md](../03-networking.md), rather than implied.

## Rust concepts met
- **`async fn`, `.await`, `tokio::spawn`, `tokio::time::timeout`** (see 06).
- **`Handle::block_on` vs `block_in_place`**: going from sync to async, and from
  async to sync.
- **Drop order = declaration order** for struct fields.
- **Exhaustive `match` caught a real gap:** adding `TransportKind::Quic` broke
  the build in `display_transport` until we decided what to show for it.
- **`#[serde(default)]` for backward compatibility:** older peers and servers
  that don't send `quic_port` deserialize as 0, meaning "no QUIC".

## Gotchas
- quinn's `read_exact` error type isn't `io::Error`, so `?` needed `.map_err`.
- An `Endpoint` must be created inside a runtime context (`runtime.enter()`).
- A punched std socket must be set non-blocking before quinn takes it over.

## Part 2 (same day): the relay

| Commit | Change |
|---|---|
| `Phase 2 step 4: relay fallback…` | Server `/relay` WebSocket (+ its first tests); client relay link; `FakeRelay`; 3 end-to-end relay tests |

### Decisions
- **Relay over WebSocket through our own server**, not a TURN server (coturn).
  It reuses the existing server, auth and deployment. Frames are already
  end-to-end encrypted, so the server learns nothing it didn't already know
  (who talks to whom, and how much). TURN can come later if relay bandwidth
  becomes a cost problem.
- **Auth in the first frame**, not an HTTP header. Simpler for every client
  (WebSocket APIs in browsers can't set headers), and the server checks it
  with the same `verify_token` the REST API uses (extracted from the `AuthUser`
  extractor for that).
- **Relay router has its own state** (`RelayState`: JWT secret plus connection
  map) and is mounted with `.merge()`, so it's testable without MongoDB or FCM.
  It produced the server's first automated tests.
- **The old `RelayOffer` signal (TURN URI/credentials) was reshaped** to
  `RelayOffer { sid }`. Nothing used it, and a protocol enum shouldn't carry
  dead variants.
- **NAT-namespace test moved to Phase 3** (needs one process per simulated
  device, i.e. `mdctl`). See 03-networking §7.

### Rust concepts met
- **`tokio::select!`**: wait on *whichever happens first*, a frame from the
  socket or a frame queued for it. Node analogy: `Promise.race` inside a loop,
  but without losing the losing branch's work.
- **axum `WebSocketUpgrade`** + `.on_upgrade(async move |socket| …)`: an HTTP
  request that turns into a long-lived WebSocket.
- **`#[cfg(test)]` on a non-test function** (`issue_token`): compiled only for
  tests, so production builds don't carry it and clippy doesn't flag it as dead code.
- **`type` aliases for complex types** (`type Conns = Arc<Mutex<HashMap<…>>>`),
  which clippy asks for once a type gets unwieldy.

### Verified
84 mdcore tests on macOS, Linux and Android, plus 3 server tests on macOS and Linux.
